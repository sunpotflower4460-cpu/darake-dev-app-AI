# Phase 0 設計固定: Darake Dev App AI

## 1. アプリの核

Darake Dev App AI は、ユーザーが最初に投げる「こんなアプリが作りたい」という魂・種を受け取り、設計、段階分解、実装依頼、確認、レビュー、通知、改善、提出準備までをやさしく束ねる開発管制室アプリです。

このアプリの目的は、ユーザーが GitHub 上で毎回 1 件ずつエージェントへ依頼し、PR を探し、CI を見て、差分を確認し、また次を依頼する負担を減らすことです。

最終的には、ユーザーが「種」を置くだけで、以下の流れを半自動で進められる状態を目指します。

```text
ユーザー: こんなアプリが作りたい
  ↓
アプリ: 設計図を作ります
  ↓
アプリ: Phase に分けます
  ↓
アプリ: Phase 1 を実行します
  ↓
確認エージェント: コード・UI・スクショ・CI を確認します
  ↓
アプリ: OK なので Phase 2 に進みます / 危険なので止めます
  ↓
アプリ: 完成しました。確認してください
  ↓
ユーザー: もっとこうしたい
  ↓
アプリ: 改善計画を作り、再実行します
  ↓
アプリ: App Store 提出準備フォームをまとめます
```

## 2. 使う人

- アプリを作りたいが、GitHub / PR / CI / デプロイ / App Store 申請を毎回細かく操作するのが負担な人
- Gemini Canvas や ChatGPT で作った原型を、GitHub 上で段階的に育てたい人
- AI エージェントに開発を任せたいが、危険な操作は止めたい人
- 難しい開発用語よりも「今どこまで進んでいるか」「次に何を確認するか」を知りたい人

## 3. MVP 範囲

初期 MVP は、まだ本物の GitHub token や App Store API には接続しません。

まずは、以下をモックで体験できる状態を完成とします。

- アプリの魂・種を入力できる
- 入力内容から設計図のたたき台を作れる
- Phase 0〜5 に分解できる
- 自動化レベルを選べる
- どこで止めるかを選べる
- 確認エージェントのチェック結果を表示できる
- 自動スクショ確認の予定欄を表示できる
- App Store 提出準備のフォーム構造を確認できる
- GitHub 実接続前でも、全体の流れがわかる

## 4. やること

- Vite + React + TypeScript で軽い Web アプリを作る
- 日本語中心のやさしい UI にする
- スマホでも見やすい 1 カラム寄りの設計にする
- 状態はまず React state と mock data で持つ
- services 層を分け、将来の GitHub 接続に備える
- CI は GitHub Actions で typecheck / build を行う
- README に使い方と今後のロードマップを書く

## 5. やらないこと

初期 MVP では以下は行いません。

- GitHub token をアプリに直接入力させる
- API key や secret をフロントエンドへ保存する
- Vercel 接続
- Firebase / Supabase 本番接続
- 課金
- 認証
- App Store への実提出
- 本番データ削除
- AI による完全自動マージ
- ユーザー確認なしの危険操作

## 6. 画面構成

### Home / Seed Intake

ユーザーが「こんなアプリが作りたい」を入力する画面。

- アプリの魂・種
- どこまで自動化したいか
- どこで止めたいか
- 完成通知の希望

### Blueprint

入力内容から作られた設計図を見る画面。

- 目的
- 使う人
- MVP
- やらないこと
- リスク
- 完成条件

### Phase Runner

Phase 0〜5 の実行計画を見る画面。

- Phase 名
- 目的
- 自動実行可否
- 手動ゲート
- 完了条件

### Review Gate

確認エージェントの結果を見る画面。

- CI 状態
- secret 混入チェック
- UI スクショ確認
- 差分レビュー
- 危険ファイル検出
- マージ可否

### Submission Hub

App Store / Google Play / Web 公開に必要な手動項目をまとめる画面。

- アプリ名
- サブタイトル
- 説明文
- キーワード
- スクショ
- プライバシー方針
- 審査メモ
- 手動提出チェックリスト

## 7. データ構造の初期方針

```ts
AppSeed
Blueprint
PhasePlan
AutomationPreference
ReviewGate
ManualGate
SubmissionDraft
```

最初は `src/data/mockProject.ts` にモックを置き、将来的に `src/services` から取得する形へ移行します。

## 8. 手動ゲート

以下は必ずユーザー確認で止めます。

- token / API key / secret の作成と登録
- GitHub App 権限追加
- 本番 DB 接続
- セキュリティルール変更
- 課金設定
- App Store / Google Play 提出
- 本番公開
- 重要な思想・中核ロジック変更
- 大規模リファクタ
- 破壊的変更

## 9. 自動で進めてよい範囲

- 設計書作成
- Phase 分解
- Issue 下書き作成
- UI 実装
- モックデータ作成
- 型定義
- コンポーネント分割
- README 更新
- GitHub Actions 追加
- PR 作成
- CI 確認
- 差分要約
- 安全レビュー

## 10. リスク判定

初期ルールは以下です。

### Low

- UI 文言変更
- CSS 調整
- README / docs 更新
- モックデータ追加
- コンポーネント分割

### Medium

- services 層追加
- GitHub API 接続の受け皿
- CI 設定変更
- 状態管理変更

### High

- secret / token を扱う変更
- 認証
- DB 接続
- 課金
- App Store 提出
- セキュリティルール
- 削除処理
- 自動マージロジック

High は必ず停止します。

## 11. 今回の初回 PR の完成条件

- React / TypeScript アプリが起動できる
- トップ画面に Darake Dev App AI の思想が表示される
- 魂・種入力欄がある
- Phase 分解のモックが見える
- Review Gate のモックが見える
- App Store 提出準備フォームの入口が見える
- GitHub Actions で build が通る
- secret が含まれない

## 12. 長期ビジョン

このアプリは、単なる自動実装ツールではなく、開発の「面倒」「怖さ」「確認漏れ」を吸収するやさしい管制室です。

ユーザーは大きな種を置く。アプリはそれを段階に分け、エージェントに渡し、進捗を見守り、危険なら止め、完成したら知らせる。

目指すのは、開発の自動化ではなく、安心して創造できる開発の庭です。
