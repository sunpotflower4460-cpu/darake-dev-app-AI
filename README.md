# Darake Dev App AI

AI開発をできるだけやさしく、自動化し、安全ゲート付きで進めるための開発管制室アプリです。

## 目指す体験

```text
ユーザー: こんなアプリが作りたい
  ↓
アプリ: 設計図を作ります
  ↓
アプリ: 段階に分けます
  ↓
アプリ: Phaseごとに実装・確認・レビューを進めます
  ↓
アプリ: 必要な場所だけ止めて通知します
  ↓
ユーザー: もっとこうしたい
  ↓
アプリ: 改善計画を作って再実行します
  ↓
アプリ: 提出準備の情報を同じ場所にまとめます
```

## Phase 2で強化したこと

- 種から生成された計画の表示
- 確認エージェントの役割表示
- 進行タイムライン
- スクリーンショット確認予定のカード
- 止めるタイミングと通知方針の見える化

## Phase 2.5で強化したこと

- 表示モードの確認欄
- 将来育てる場所の整理
- 仮データで動いている欄の見える化
- 実運用に進む前の安全な境界づくり

## Phase 3.6で強化したこと

- `scripts/buildState.mjs` で `public/repo-state.json` を更新する導線
- `npm run state:build` コマンド
- 手動実行専用の `Update State File` workflow
- 変更がある時だけ状態ファイルをコミットする仕組み

## Phase 3.7で強化したこと

- 状態ファイルの鮮度判定
- 「だらけてOK」か「軽く確認すると安心」かの表示
- 古い状態の時だけ更新を促すメッセージ
- 確認に使う力を減らすための見える化

## Phase 3.8で強化したこと

- だらけモードの中核UI
- 「今やる / 後でいい / 放っておいていい」の仕分け
- 全部を頑張らず、大事なところにだけ力を残す設計
- だらけることを開発戦略として扱う画面

## Phase 3.9で強化したこと

- だらけモードと状態鮮度の連動
- 状態が新しい時は確認タスクを「放っておいていい」へ移動
- 状態が古い時だけ確認タスクを「今やる」へ移動
- 見張らなくても自然に必要なことだけ浮かぶ導線

## Phase 4で強化したこと

- 作りたいアプリの種からIssue下書きを表示
- 目的、背景、やること、完了条件、まだやらないことを整理
- エージェントに渡す文を用意
- 実際の投稿前に確認できる安全な下書き段階

## Phase 4.1で強化したこと

- Issue下書きをMarkdown形式に整形
- Issue本文をワンタップでコピー
- コピー成功/失敗の表示
- 投稿前に文章だけを安全に持ち出せる導線

## Phase 4.2で強化したこと

- コピー前にIssue下書きを編集できるフォーム
- タイトル、目的、背景、やること、完了条件を画面上で調整
- 一行ずつ編集したリストをMarkdown本文へ反映
- 投稿前に文章を整えてからコピーできる導線

## Phase 4.3で強化したこと

- 編集中のIssue下書きをブラウザに一時保存
- 画面を閉じても編集内容が残りやすい導線
- 初期状態に戻すボタン
- 投稿前の安全な保存だけに限定

## Phase 6.0で固定したこと

- GitHub実データ連携は読み取り専用から始める
- tokenやsecretをブラウザへ出さない
- GitHub Actionsで状態JSONを生成し、publicへ出す情報を選別する
- 不明な状態は自動実行せずmanualへ寄せる
- 書き込み操作はPhase 7以降で個別に安全設計する

## Phase 6.1で強化したこと

- GitHub Actionsでopen PR一覧を読み取り
- `snapshot/pr-watch.json` をartifact生成
- `npm run pr:build` コマンド
- publicへの自動反映なしで、読み取り専用のPR監視土台を追加

## 初期版でできること

- 魂・種の入力
- 設計図の確認
- Phase分解の確認
- 確認ゲートの見える化
- 自動スクショ確認の予定表示
- App Store提出準備フォームの入口

- 課金
- 認証
- App Storeへの実提出
- 危険な自動実行
- 確認なしのIssue投稿

```bash
npm run build

npm run pr:build
```

## 手動で状態ファイルを更新する流れ

GitHub Actions の `Update State File` を手動実行すると、`public/repo-state.json` が更新されます。

GitHub Actions の `Update Review Watch File` を手動実行すると、`public/review-watch.json` が更新されます。

GitHub Actions の `Update PR Watch File` を手動実行すると、`public/pr-watch.json` が更新されます。

これらのworkflowは常時自動実行ではありません。必要な時だけ実行する安全寄りの導線です。

## 方針

このアプリは、ユーザーの代わりに危険な操作を勝手に進めるものではありません。

普段の細かい開発作業はできるだけ自動化し、外部連携・本番公開・提出・大きな方向転換などの大事な場面では必ず止まる、やさしい開発管制室を目指します。

大事なのは、ずっと真面目に見張ることではなく、だらけていても必要な時だけ気づけることです。
